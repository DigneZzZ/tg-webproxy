# Changelog

Версия хранится в `TGWP_VERSION` внутри `tg-webproxy.sh` и должна подниматься при каждом изменении: по ней работают проверка обновлений и `tgwebproxy self-update`.

## 1.4.1 — 2026-10-06

- Косметика: строка «Путь:» после шага base path печатала slug дважды (интерполяция `${BASEPATH:+…}` и `${BASEPATH:-…}` рядом).

## 1.4.0 — 2026-10-06

- **Base path (скрытый путь).** Транспорт живёт под `/<slug>/`, а не в корне домена — на типовых путях сканер видит только сайт. Ссылки принимают вид `server=домен%2Fslug` с маркированным секретом (`base64url(0x70‖hex)`); старые клиенты честно просят обновиться вместо молчаливого слома. Новым установкам slug генерируется по умолчанию, переустановка хранит текущий путь; `none` — корень как раньше (`TGWP_BASEPATH`).
- **Обход post-quantum-бага Android.** Caddyfile получает `tls { curves x25519 secp256r1 }` и `header -Via`: Google Play-сборки Telegram Android 12.10.x не подключаются, когда сервер выбирает `X25519MLKEM768` (bugs.telegram.org/c/66121, открыт), а Caddy на Go ≥ 1.24 предлагает его по умолчанию. Вернуть PQ: `TGWP_PQ_TLS=1`. Идемпотентно, с `caddy validate` перед применением.
- **`TGWP_SITE_UPSTREAM=http://127.0.0.1:порт`** — сайт-прикрытие как reverse-proxy на ваше приложение (режим B апстрима, `--site-upstream`).
- **NAT-фикс.** Раньше `--nat-info` попадал в запуск MTProxy только при заданном AD_TAG. Теперь схема апстрима: `MTPROXY_NAT_ARGS` в `mtproxy.env` и неэкранированный `$MTPROXY_NAT_ARGS` в ExecStart drop-in — NAT-аргументы переживают любую перезапись секретов/тега.
- `tgwebproxy update` предупреждает о миграции на подписанные carrier-токены (`token.key` + дрейн легаси-токенов в `update-relay.sh`); `uninstall` чистит drop-in каталог `tproxy-server.service.d`; клиентские подсказки обновлены (Desktop ≥ 7.2 для путей, iOS/macOS — нет, t.me-маршрут по-прежнему не зарегистрирован). Обходы umask-багов апстрима (203/EXEC, упавший тест) сохранены для `TGWP_REF`-пинов — сам апстрим исправил их 29.09.

## 1.3.0 — 2026-09-03

Первый релиз в отдельном репозитории. До этого скрипт жил в `dignezzz.github.io/server/`, откуда теперь публикуется зеркало.

- Split-режим: роли `front` и `backend`, `systemd-socket-proxyd` на loopback, nftables-ограничение порта MTProxy адресами туннеля, команды `backend`, `secrets`, `allow`, отдельная панель для backend-хоста.
- Меню и панель переработаны: рамка с вердиктом, секции в два столбца, сгруппированные действия в одну клавишу, живой монитор без внешнего `watch`.
- Убран SSH-фильтр: не задача этой утилиты.
