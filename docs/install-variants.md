# Варианты установки

Одна и та же команда, поведение зависит от терминала и переменных окружения.

```bash
bash <(wget -qO- https://raw.githubusercontent.com/DigneZzZ/tg-webproxy/main/tg-webproxy.sh)
```

## Интерактивно

Установщик проходит шаги 0–9 и спрашивает только то, что нельзя вывести сам:

| Шаг | Что происходит |
|---|---|
| 0 | Роль хоста: `single` по Enter, `front` или `backend` для [split-режима](split-mode.md) |
| 1 | Зависимости, внешний IPv4, занятость портов 80/443 |
| 2 | Домен и почта. Все A-записи домена сверяются с IP сервера сразу при вводе, при расхождении можно ввести другой домен или продолжить осознанно. CDN перед доменом определяется по заголовкам |
| 3 | Секрет: свой, сгенерированный или оставшийся от прошлой установки |
| 4 | Тип подключения: `https` (по умолчанию), `https-lanes`, `websocket`, `websocket-lanes`, `all` |
| 5 | AD_TAG от @MTProxybot, необязательно. Печатается точная подсказка: адрес `домен:443` и секрет для бота |
| 6 | Сайт-прикрытие: свой каталог или сгенерированная уникальная заглушка |
| 7 | Загрузка апстрима, установка утилиты, сборка. Прогресс одной строкой, вывод в `/var/log/tgwebproxy-install.log` |
| 8 | Применение выбранного типа подключения (если не `https`) |
| 9 | Синхронизация секретов и AD_TAG с MTProxy, счётчики трафика |

## Без вопросов: переменные окружения

Любая переменная имеет приоритет над вопросом. Если терминала нет, недостающие значения берутся из прошлой установки, иначе установщик завершается с кодом 2.

```bash
TGWP_HOSTNAME=proxy.example.com \
TGWP_EMAIL=admin@example.com \
TGWP_MODE=all \
TGWP_YES=1 \
bash <(wget -qO- https://raw.githubusercontent.com/DigneZzZ/tg-webproxy/main/tg-webproxy.sh)
```

| Переменная | Значение |
|---|---|
| `TGWP_HOSTNAME` | домен с A-записью на сервер |
| `TGWP_EMAIL` | почта для Let's Encrypt |
| `TGWP_SECRET` | 32 hex, можно с префиксом `dd`; пусто = сгенерировать или оставить прошлый |
| `TGWP_MODE` | `https` \| `https-lanes` \| `websocket` \| `websocket-lanes` \| `all` |
| `TGWP_ADTAG` | 32 hex от @MTProxybot |
| `TGWP_WORKERS`, `TGWP_MAXCONN` | воркеры и лимит соединений MTProxy (1 и 4096) |
| `TGWP_SITE_DIR` | каталог своего сайта с `index.html` |
| `TGWP_REF` | закрепить коммит, тег или ветку `tproxy-server` |
| `TGWP_YES=1` | отвечать «да» на все подтверждения |
| `TGWP_NO_UPDATE_CHECK=1` | не проверять новую версию скрипта |
| `TGWP_ROLE`, `TGWP_BACKEND`, `TGWP_SECRETS`, `TGWP_ALLOW_FROM` | [split-режим](split-mode.md) |

## Свой сайт-прикрытие

Лучшая маскировка — настоящий сайт. Каталог должен содержать `index.html`, файлы должны читаться пользователем `tproxy` (`chmod -R o+r`, каталогам `o+x`). Ограничения relay: без inline-стилей и скриптов, без форм и внешних ресурсов (CSP апстрима это запрещает), `favicon.svg` отвечает и на `/favicon.ico`, `404.html` — страница «не найдено».

```bash
TGWP_SITE_DIR=/root/mysite bash <(wget -qO- …/tg-webproxy.sh)
```

Сайт копируется в `/srv/tproxy-site`. Позже его можно править на месте и перезапускать relay: `systemctl restart tproxy-server`.

Если каталог не указан, генерируется заглушка на 5 страниц. Она рандомизирована по названию, цветам, шрифтам, разметке, набору страниц и `robots.txt`, так что две установки не совпадают по отпечатку, но остаётся визиткой и для серьёзной маскировки её стоит заменить.

## Закрепить версию апстрима

```bash
TGWP_REF=52a5feb bash <(wget -qO- …/tg-webproxy.sh)
```

По умолчанию берётся HEAD ветки апстрима. `tgwebproxy update` обновляет relay до текущего HEAD с автоматическим откатом, если новый бинарник не проходит проверку или не отвечает на healthz.

## Переустановка

Та же команда поверх существующей установки. Домен, почта, секрет, режим и AD_TAG подставляются из `/opt/tgwebproxy/info.env` по Enter, `/srv/tproxy-site` сохраняется, Caddyfile и конфиги перезаписываются. Перед запуском апстрима снимается наш drop-in для MTProxy и чинятся права на бинарник, чтобы повторная установка не упала на тех же местах, что и первая.

## Проверка после установки

```bash
tgwebproxy                      # панель
curl -fsS http://127.0.0.1:8081/readyz    # ready
curl -fsS https://proxy.example.com/      # сайт-прикрытие
```

Клиенту нужен Telegram Desktop 7.1.1+ или Android beta 12.10.2+. Публичный `t.me` пока не регистрирует маршрут `/webproxy`, для проверки используйте ссылку `tg://webproxy?…` или ручной ввод: Настройки → Продвинутые → Тип соединения → Добавить прокси → WEB.
